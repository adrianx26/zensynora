    Agent Swarm Guide¶

    Applies to: v0.7.1 · Reviewed: 2026-10-13. v0.7.1: delegation works again (before, every delegate call answered "Agent registry not initialized"), and in the Web UI each hand-over between agents — delegation or swarm — is shown in the chat channel and its Activity panel (Web UI guide). Commands use the installed zensynora CLI (python cli.py … from the source folder is equivalent).

    Overview¶

    Agent Swarms is a powerful multi-agent coordination system for MyClaw that enables multiple AI agents to collaborate on complex tasks. Instead of relying on a single agent, swarms distribute work across specialized agents using various coordination strategies.

    Quick Start¶

    1. Basic Parallel Swarm¶

    # Create a research team
swarm_create(
    name="research_team",
    strategy="parallel",
    workers="researcher1,researcher2,researcher3",
    aggregation="synthesis"
)
# Returns: swarm_abc123def456

# Assign a task
swarm_assign(
    swarm_id="swarm_abc123def456",
    task="Research quantum computing breakthroughs in 2024"
)

    2. Sequential Pipeline¶

    # Content creation workflow
swarm_create(
    name="blog_pipeline",
    strategy="sequential",
    workers="outline_writer,content_writer,editor",
    aggregation="concatenation"
)

swarm_assign(
    swarm_id="swarm_xyz789",
    task="Write an article about Python async programming"
)
# Output flows: Outline → Draft → Edited Content

    3. Hierarchical with Coordinator¶

    # Code review with lead developer
swarm_create(
    name="security_review",
    strategy="hierarchical",
    coordinator="lead_security_expert",
    workers="sql_injection_checker,auth_reviewer,input_validator",
    aggregation="synthesis"
)

swarm_assign(
    swarm_id="swarm_sec456",
    task="Review this login module for security vulnerabilities"
)
# Coordinator plans, delegates, and synthesizes results

    4. Voting for Decisions¶

    # Multiple agents vote on architecture decision
swarm_create(
    name="architecture_vote",
    strategy="voting",
    workers="architect1,architect2,architect3,architect4",
    aggregation="consensus"
)

swarm_assign(
    swarm_id="swarm_vote123",
    task="Should we use microservices or monolith?"
)
# Consensus determines the winning approach

    Configuration¶

    Add to your ~/.myclaw/config.json:

    {
  "swarm": {
    "enabled": true,
    "max_concurrent_swarms": 3,
    "default_strategy": "parallel",
    "default_aggregation": "synthesis",
    "timeout_seconds": 300,
    "swarm_memory_limit": 50
  }
}

    Configuration Options¶

    Option Default Description
    enabled true Enable/disable swarm functionality
    max_concurrent_swarms 3 Maximum parallel swarms per user
    default_strategy "parallel" Default execution strategy
    default_aggregation "synthesis" Default result aggregation
    timeout_seconds 300 Maximum execution time
    swarm_memory_limit 50 Max messages stored per swarm

swarm_assign(

    Flow: Research → Outline → Draft → Edit → SEO Optimize

    Best Practices¶

    1. Agent Selection¶

    Complementary Skills: - Research team: researcher1, researcher2, researcher3 (different specialties) - Code review: security_expert, performance_reviewer, style_checker - Content: researcher, writer, editor

    Coordinator Selection: - Should have good planning capabilities - Needs to understand the big picture - Prefer models with strong reasoning

    2. Strategy Selection Guide¶

    Task Type Strategy Why
    Research/Broad Analysis Parallel Multiple perspectives simultaneously
    Content Creation Sequential Progressive refinement
    Complex Multi-part Tasks Hierarchical Orchestrated subtasks
    Decision Making Voting Consensus validation
    Code Review Parallel or Hierarchical Different aspects or orchestrated
    Data Processing Sequential Step-by-step transformation

    3. Aggregation Selection¶

    Goal Method Example
    Get diverse perspectives Concatenation Research reports
    Find best single answer Best Pick Code solutions
    Quick agreement Consensus Yes/No decisions
    Comprehensive summary Synthesis Final reports

    4. Resource Management¶

    # Check current usage
swarm_stats()

# Clean up old swarms
swarm_list(status="completed")  # Find completed
swarm_terminate("swarm_old123")  # Clean up

    API Reference¶

    Core Functions¶

    swarm_create()¶

    Create a new swarm.

    Parameters: - name (str): Descriptive name for the swarm - strategy (str): One of: parallel, sequential, hierarchical, voting - workers (str): Comma-separated list of agent names - coordinator (str, optional): Coordinator agent name (required for hierarchical) - aggregation (str): One of: consensus, best_pick, concatenation, synthesis - user_id (str, optional): User identifier

    Returns: Swarm ID (e.g., swarm_abc123def456)

    swarm_assign()¶

    Execute a task with the swarm.

    Parameters: - swarm_id (str): Swarm identifier - task (str): Task description/prompt - user_id (str, optional): User identifier

    Returns: Formatted results including: - Individual agent outputs - Confidence score - Execution time - Aggregated final result

    swarm_status()¶

    Get current swarm status.

    Parameters: - swarm_id (str): Swarm identifier

    Returns: Status information (pending, running, completed, failed, terminated)

    swarm_result()¶

    Get detailed execution result.

    Parameters: - swarm_id (str): Swarm identifier

    Returns: Complete result with individual agent outputs

    swarm_terminate()¶

    Force stop a running swarm.

    Parameters: - swarm_id (str): Swarm identifier

    swarm_list()¶

    List all swarms.

    Parameters: - status (str, optional): Filter by status - user_id (str, optional): User identifier

    swarm_stats()¶

    Get usage statistics.

    Parameters: - user_id (str, optional): User identifier

    Returns: Statistics including counts, avg confidence, execution times

    Troubleshooting¶

    Common Issues¶

    "Maximum concurrent swarms reached"¶

    Cause: Hit the max_concurrent_swarms limit

    Solutions: 1. Wait for existing swarms to complete 2. Terminate unused swarms: 

    swarm_list(status="running")
swarm_terminate("swarm_xxx")
    3. Increase limit in config: 
    {"swarm": {"max_concurrent_swarms": 5}}

    "Agent not found in registry"¶

    Cause: Agent name doesn't exist in the agent registry

    Solution: Check available agents and correct the name: 

    # List available agents
# (Check your config.json agents.named section)

    Swarm execution timeout¶

    Cause: Task took longer than timeout_seconds

    Solutions: - Break task into smaller parts - Increase timeout in config - Use fewer workers for faster execution

    Low confidence scores¶

    Cause: Agents disagree significantly or quality varies

    Solutions: - Try different aggregation method - Provide clearer, more specific task description - Add more workers (for voting strategy) - Use coordinator for better synthesis

    Storage¶

    Swarm data is stored in ~/.myclaw/swarm.db:

    Tables¶

    swarms - Swarm configurations and status - Strategy, workers, coordinator settings

    swarm_tasks - Individual task assignments - Input/output data

    swarm_messages - Inter-agent communication log - Useful for debugging

    swarm_results - Execution results - Individual and aggregated outputs

    Cleanup¶

    Old swarms are automatically cleaned up after 30 days. You can manually clean up:

    # In Python code
from myclaw.swarm import SwarmStorage
storage = SwarmStorage()
deleted = storage.cleanup_old_swarms(days=7)
print(f"Cleaned up {deleted} old swarms")

    Advanced Usage¶

    Custom Strategies¶

    You can extend the system with custom strategies by inheriting from BaseStrategy:

    from myclaw.swarm.strategies import BaseStrategy

class MyCustomStrategy(BaseStrategy):
    async def execute(self, task, workers, coordinator=None):
        # Your custom logic here
        pass

    Direct Orchestrator Access¶

    For programmatic control:

    from myclaw.swarm import SwarmOrchestrator, SwarmConfig, SwarmStrategy

orchestrator = SwarmOrchestrator(agent_registry, config)

# Create swarm
config = SwarmConfig(
    name="my_swarm",
    strategy=SwarmStrategy.PARALLEL,
    workers=["agent1", "agent2"]
)
swarm_id = await orchestrator.create_swarm(config)

# Execute and get result object directly
result = await orchestrator.execute_task(swarm_id, "My task")
print(result.confidence_score)
print(result.individual_results)

    Summary¶

    Agent Swarms enable powerful multi-agent collaboration through:

    1. Four Strategies - Parallel, Sequential, Hierarchical, Voting
    2. Flexible Aggregation - Combine results intelligently
    3. Coordinator Role - For complex orchestrated tasks
    4. Persistent Storage - Track and analyze swarm operations
    5. Easy Integration - Works with all existing MyClaw features

    Start simple with Parallel strategy, then explore Hierarchical with a Coordinator for complex workflow
