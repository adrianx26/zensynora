    Development Workflow¶

    Prerequisites¶

    • Python 3.11+
    • System dependencies (e.g., git, curl, sqlite3)

    Installation¶

    # Clone the repository
git clone https://github.com/adrianx26/zensynora.git
cd zensynora

# Recommended installer creates and installs into an isolated virtual environment
chmod +x install.sh
./install.sh

# Or install manually:
python3 -m venv .venv
source .venv/bin/activate   # Linux / macOS
python -m pip install -r requirements.txt

    On Windows PowerShell, replace the manual setup commands with py -m venv .venv, .\.venv\Scripts\Activate.ps1, and python -m pip install -r requirements.txt. Do not install packages into the OS-managed Python or bypass PEP 668 with --break-system-packages. install.sh checks for venv support and offers to install python3-venv on Debian/Ubuntu when missing; it also offers to recreate an invalid existing environment. Use ./install.sh --no-docker --recreate-venv to request recreation directly.

    Quick Start¶

    1. Run the onboarding wizard to generate ~/.myclaw/config.json: 
      python cli.py onboard
    2. Choose your LLM provider, API keys, and optional Telegram/WhatsApp credentials.
    3. Start an agent: 
      python cli.py agent

    Running Tests¶

    # Activate virtual environment
source .venv/bin/activate

# Run all tests
python -m pytest tests/ -v

# Run specific test files
python -m pytest tests/test_agent.py -v
python -m pytest tests/test_provider_retry.py -v
python -m pytest tests/test_swarm_aggregation.py -v
python -m pytest tests/test_memory_batching.py -v
python -m pytest tests/test_tool_rate_limiting.py -v

# Run with coverage
python -m pytest tests/ -v --cov=myclaw --cov-report=html

    Linting & Formatting¶

    # Install linting tools
python -m pip install flake8 black isort  # Run with the virtual environment active
# Lint the codebase
flake8 .
# Auto‑format with black
black .
# Sort imports
isort .

    High‑Level Architecture (from README)¶

    Channels (CLI, Telegram)  ↓
   Agent  →  Memory (SQLite)  Provider (Ollama, Cloud)  Tools (shell, network)  Swarms (multi‑agent)
    • Memory: Per‑user SQLite with FTS5, observations, relations.
    • Providers: Local (Ollama, LM Studio) or Cloud (OpenAI, Anthropic, Gemini, Groq, OpenRouter).
    • Agent Swarms: Four strategies – parallel, sequential, hierarchical, voting.
    • Channels: Telegram & WhatsApp gateways (configurable, per‑user whitelist).
    • Toolbox: Dynamic Python tools with documentation, stored in ~/.myclaw/TOOLBOX/.
    • Knowledge Base: Markdown notes with YAML frontmatter, stored in ~/.myclaw/knowledge/{user_id}/.

    Common Commands (CLI)¶

    Tool Description
    shell(cmd) Execute a command from the allowlist (ls, git, curl, etc.)
    write_file(path, content) Write a file inside the workspace
    read_file(path) Read a file (validated against path traversal)
    delegate(agent, task) Send a task to another agent
    register_tool(name, code, docs) Add a new tool to TOOLBOX
    swarm_create(name, strategy, workers, coordinator, aggregation) Create a new swarm
    swarm_assign(swarm_id, task) Execute a task in a swarm
    write_to_knowledge(title, content) Save a note to the knowledge base
    search_knowledge(query) Search notes with FTS5

    Building & Packaging (Future)¶

    • No dedicated build script currently. When packaging, ensure:
    • Include the myclaw/ package and all sub‑modules.
    • Ship cli.py, onboard.py, and requirements.txt.
    • Document environment variable overrides in myclaw/config.py (ENV_OVERRIDES mapping).

    Guidelines for Future Developers¶

    1. Follow the existing pattern for new tools:
    2. Provide clear documentation.
    3. Include try/except and log errors.
    4. Register the tool with a unique name.
    5. When adding a new provider:
    6. Add the provider to ProvidersConfig in myclaw/config.py.
    7. Implement the provider client in myclaw/provider.py with a uniform chat() method.
    8. Test with both local and cloud endpoints.
    9. Agent Swarms:
    10. Use the AgentDiscovery class to suggest agents for a task.
    11. Keep the number of workers per swarm bounded by the max_concurrent_swarms setting.
    12. Security:
    13. All file operations go through validate_path() – do not bypass it.
    14. Shell commands must be whitelisted; avoid dynamic command construction.
    15. Testing:
    16. Tests are in tests/ and use pytest. Write unit tests for new tools and integration tests for swarms.
    17. Use coverage to ensure new code is well‑covered.
